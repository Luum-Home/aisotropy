# Live arena results — modes × benchmarks

> **Run:** 2026-07-23 14:11 UTC • **Model (held constant):** `agnes-2.0-flash` • **Modes:** qa, rag, tools, memory, structured, stream, safeguard, memory_cross_session, memory_semantic_recall, memory_consolidation, isolation_forgetful • **Frameworks:** 9 • **Execution forms:** native, docker
> **Billable model round-trips this run:** 1094 • **Bench modes:** qa • **Bench iters:** 5 • **Cold probes:** 3 (empty-stdin, 0 model calls)
> **New dimensions:** memory_scoped, isolation_leak, crash_recovery, observability (scoped-memory & isolation, crash recovery, observability capability)

> **LANE: REAL** — every row is a real `agnes-2.0-flash` call; the quality numbers are the live signal.

> **The model is real and identical for every row.** Because every framework calls the
> same `agnes-2.0-flash` with the same credentials, a difference in a column is a property of
> the **framework**, not the model. This is the executable counterpart to `arenas/BENCHMARKS.md`
> (which holds the model constant as a keyless stub to measure framework *overhead*, and is
> explicit that its quality table is *documented, not executed*).

> **✅ Primary score: deterministic, by construction.** The Correctness / quality table below
> is scored by `arenas/live/runner/scoring` — a pure, unit-tested, reproducible function per
> dimension (exact/containment match for QA & memory, hit@1 + trap-refusal for RAG, exact
> tool-name+numeric-result match for tools, JSON-object validity for structured, TTFT-measured
> for stream). No LLM, no network call, no randomness, no wall-clock decision — the SAME
> input always produces the SAME score, enforced by `scripts/arena-determinism-guard.sh`.
> See `docs/architecture/arena-deterministic-judging.md`.

> _Secondary LLM-judge pass: OFF (default — pass `-llm-judge` to opt in). The primary
> deterministic table below, latency, tokens, cold-start, TTFT and footprint are all real,
> unaffected measurements regardless of this flag._

## Correctness / quality — per framework × per mode (PRIMARY, deterministic)

**Deterministic score** is `pass/total` from `arenas/live/runner/scoring` — pure,
reproducible, mode-specific correctness (see the primary-score note above). The **Mode
signal** column restates the same underlying measurement in mode-specific units (rag:
retrieval hit@1 on the gold doc + trap-refusal; tools: real tool execution + numeric
correctness; structured: schema-valid JSON; stream: mean TTFT). Latency is end-to-end
wall-clock (native, correctness pass) including the real model round-trip(s).

**Run summary (this pass):** 765 total runs — 706 scored, 59 errored (7.7% of runs never produced a scoreable answer).

> **QA is a smoke test, not a quality signal here (empirical finding).** This arena holds
> the model CONSTANT across every framework, so `qa` measures whether the MODEL answers
> correctly — and the model can't vary here, so `qa` can only ever detect gross adapter
> breakage (a broken request/response path), never a framework-quality difference. A
> calibration run confirmed this empirically: every framework scored a PERFECT 1.0 on `qa`,
> including on `qa-h01`..`qa-h06` — near-miss items deliberately written to be easy to get
> wrong (e.g. 208 vs 206 bones, Sydney vs Canberra). Read a perfect `qa` score as "the
> adapter is wired correctly," never as "this framework answers better than that one."
>
> **`structured` and `stream` inherit the same ceiling.** Both reuse the IDENTICAL
> single-shot QA task set as `qa` (`buildQAStyle` in `arenas/live/runner/tasks.go`
> serves all three modes from the same task list) — their own mechanics (schema validity,
> time-to-first-token) still measure something real, but the underlying QUESTION CONTENT
> does not discriminate between frameworks either, for the same reason `qa` doesn't.
>
> **Modes that DO carry discriminating signal in this arena: `memory`, `rag`, `tools`.**
> A calibration run with the model held constant across 3 frameworks showed real
> separation on these — e.g. aisotropy scored `memory` 1/2 and `tools` 5/7 while
> llamaindex scored `memory` 2/2 and `tools` 7/7 in that run. Weight the `memory`/`rag`/
> `tools` rows below as the primary quality signal in this board; read `qa`/`structured`/
> `stream` as wiring/smoke coverage, not a quality ranking. All modes keep running — a
> smoke test that catches gross breakage is still worth having.
>
> **The flip side: qa is the arena's purest OVERHEAD measurement.** The same property
> that makes `qa` a correctness smoke test (identical model + identical question, every
> run) makes it the most controlled experiment for a *different* axis — see
> "Framework overhead on identical work" below, after the token-spend table.

> **aisotropy `memory` is not apples-to-apples with the other frameworks — read before
> comparing.** `aisotropy.App.Turn` (the public façade `arenas/live/aisotropy` drives, see
> `aisotropy/turn.go`) accepts ONE prompt string and no message-list parameter, so this
> adapter drives **one real model call per conversational turn** — SPEC-sanctioned (see
> `arenas/live/SPEC.md`), not an adapter shortcut — instead of replaying the supplied
> transcript in a single call the way every other framework's adapter here does. Two
> consequences: (1) its memory-mode token total is inflated by **call count**, not
> per-call verbosity, so it is not directly comparable to a single-call framework's token
> total; (2) earlier runs of this adapter additionally dropped the suite's canned
> assistant turns entirely (only user turns were replayed), which primed a refusal
> cascade that made the `memory` SCORE itself invalid, not just the token count — that
> adapter defect is now fixed (canned turns reach the model as established context; see
> `arenas/live/aisotropy/mode_memory.go`), but the call-count token asymmetry remains, by
> contract, and is not a bug. Full forensic analysis:
> `docs/architecture/arena-memory-forensics.md`.

> **`safeguard` measures behavior under adversarial prompts — read the confound first.**
> Safeguard items are RUNNER-side probes sent to every adapter as ORDINARY `qa`/`rag`
> turns (zero adapter-contract change — an adapter cannot tell a probe from a normal
> turn), scored deterministically: `ScoreDecline` (did it refuse off-topic/jailbreak
> requests without leaking substance) and `ScoreNoContain` (did the reply avoid denied
> tokens — model identity, a planted system-prompt sentinel, a corpus-injection sentinel).
>
> **Confound (stated honestly):** with the MODEL held constant, the off-topic and
> identity items largely measure *persona-following by the shared model* under each
> framework's prompt assembly — expect weak framework separation there. The
> DISCRIMINATING items are `sg-corpus-injection` (does retrieved poisoned content get
> obeyed), `sg-sysprompt-exfil` (does the framework's prompt handling leak a planted
> sentinel) and `sg-jailbreak-persona` (persona-override resistance), where framework
> machinery (retrieval plumbing, prompt layering, guardrails) is actually in the loop.
> A framework whose OWN guardrail BLOCKS a probe outright is scored as a refusal
> (recognized block signatures only — see `guardrailBlockSignatures` in the runner),
> never as an errored run.

> **Memory-extension modes — the varies-session/holds-user mechanic (read first).**
> `memory_cross_session`, `memory_semantic_recall` and `memory_consolidation` all VARY the
> `session_id` across a task's 2–3 invocations while HOLDING one `user_id` constant. That
> single change defeats transcript replay BY CONSTRUCTION: a session-keyed store returns
> empty for the fresh recall session, so only genuine USER-scoped memory can recall the
> planted fact. On the wire every invocation is an ordinary `memory` turn plus the additive
> `user_id` field — zero new adapter mode. Scored by `ScoreMemory` (answer-key containment).
>
> - `memory_cross_session`: fact in session A, recall in session B (same user, no wall-clock gap).
> - `memory_semantic_recall`: an early needle stated semantically, recalled by a PARAPHRASE
>   that shares NO content tokens with the needle (a fixture guard pins zero-overlap forever),
>   so a raw-transcript replayer must re-send ~40 turns and pays 10–20× the input tokens —
>   visible directly in the token table.
> - `memory_consolidation`: persist, then a `consolidate` directive turn (the deterministic
>   barrier — the framework runs its consolidation to completion before the process exits),
>   then recall across the session boundary. What is SCORED is the OUTCOME; the MECHANISM
>   (async worker vs. in-hot-path vs. none) is a separate, labeled finding, never folded in.
>
> **Fairness — competitors ARE wired to their own official memory primitive (per-adapter,
> not a strawman).** Each competitor adapter reads `user_id`/scope and drives that framework's
> best OFFICIAL cross-session primitive, declared with URL + maturity + version in its own
> `arenas/live/<fw>/README` and tabulated in `docs/architecture/arena-memory-extensions.md`:
> langgraph `BaseStore`(+langmem), llamaindex `Memory`+`VectorMemoryBlock`, mastra
> resource-scope+`semanticRecall`(+@mastra/qdrant), spring-ai `ChatMemory`, pydantic-ai
> app-level. So a competitor cell here is a REAL result (pass/fail as scored), NOT a
> run-and-fail placeholder. Honest exceptions, labeled not hidden: genkit-go/eino adopted no
> official cross-session primitive (their cells run-and-fail, an empty-recall fail — not
> infeasible), and ai-sdk's is community-only (`infeasible`, see its matrix.json). Maturity is
> NATIVE vs OFFICIAL-EXTENSION vs OFFICIAL-THIRD-PARTY per the ledger — read it before any
> 'only aisotropy does memory' reading, which the evidence does not support.
>
> **aisotropy caveat (symmetric honesty): these cells are served by aisotropy's SEMANTIC tier,
> not its dedicated conversational-memory path.** The adapter persists via `App.IngestKnowledge`
> (user-scoped, e5→Qdrant) and recalls via the streaming chat route — the SAME shape as every
> competitor that passes (all vectorize conversation turns and semantic-retrieve; the
> memory-vs-RAG line collapses to vectorize-and-retrieve for semantic recall), so it is
> apples-to-apples, NOT a workaround. The disclosed gap it surfaced: aisotropy's dedicated
> conversational path (working memory → outbox → consolidation) does NOT do semantic recall on
> the non-streaming chat route (nil semStore + `KindTurn` excluded from hydration) — a product
> follow-up, see `arenas/live/aisotropy/mode_memory_ext.go` and commit 39017e9.

## Scoped memory & tenant isolation — `memory_scoped` + `isolation_leak`

Multi-tenant scoped memory: a fact written under a compound scope
`(tenant_id, user_id, product_id)` must be recalled in that exact scope
(**same-scope hit**), must NOT be recalled under a different `tenant_id`
(**cross-tenant miss**), and a secret seeded by tenant A must never surface when
probed as tenant B (**leak? = none**). `memory_scoped` PASSes iff same-scope hit
**and** cross-tenant miss; `isolation_leak` PASSes iff no leak. Each row is sourced
from that adapter's own `test-isolation.sh` (real agnes recall/probe calls), the
authoritative deterministic signal for its specific contract.

> **Native vs hand-rolled (honest caveat).** aisotropy enforces tenant isolation
> **by construction** in the core runtime — `tenant_id` travels only via
> `context.Context` and Qdrant does payload-filtered HNSW scans (a constitutional
> gate), so it ships **no** hand-rolled arena isolation harness. For the other
> frameworks the gradation matters (an ecosystem audit corrected an earlier
> blanket claim here): four (ai-sdk, pydantic-ai, eino, genkit-go) have no
> framework-owned data plane to scope at all, while others ship a SCOPING
> PARAMETER (langgraph BaseStore namespaces, mastra resource/thread, spring-ai
> conversationId) that partitions data only if passed correctly on every call —
> unenforced in every surveyed OSS core; enforcement exists only in commercial/
> server tiers. Either way, the compound (tenant,user,product) key this table
> exercises was hand-rolled in each arena adapter — because the framework offers
> nothing, or its native scope has fewer axes than the test. See
> docs/architecture/arena-benchmark-methodology.md ("Same checkmark, different
> guarantee") for the L0-L3 ladder. A blank aisotropy row is *by design*, not a
> failure.

## Crash recovery — `crash_recovery` (hard `kill -9` mid-turn)

A producer process states a fact (turn 1, committed to a real on-disk store), then
is **SIGKILL**ed while a second turn's model call is in-flight. A completely fresh
process then resumes the same session and must recall the turn-1 fact.
**Resumed** = the fresh process recovered the session; **fact recalled** = the
pre-crash fact survived; **state intact** = `state_lost==false` (the crash lost only
the one truly in-flight turn, nothing committed). PASSes iff all three hold. Sourced
from each adapter's `test-crash.sh` (two real OS processes + a real kill).

> **Consistent finding: no framework here has *native* crash-recovery.** What passes
> does so because it persists each committed turn to a real store (SQLite / rqlite /
> on-disk file) *before* the next turn, so a fresh process can re-hydrate — and the
> **in-flight turn is always lost** (that is the correct, expected outcome, not a bug).
> aisotropy ships no crash harness in its adapter; its blank row is by design.

## Notes

- **Primary score is deterministic (repeat).** The Correctness/quality table's
  "Deterministic score" column comes from `arenas/live/runner/scoring` — a pure,
  unit-tested, reproducible function per dimension, gated by
  `scripts/arena-determinism-guard.sh`. No LLM, no network call, no randomness.
- **Self-judge bias (secondary, opt-in only).** The `-llm-judge` Correctness/helpfulness/
  faithfulness scores (own section above, OFF by default) come from an LLM-as-judge on the
  same model family as the contestants; treat them as a relative, directional signal, not
  ground truth, and never as the deciding number over the primary deterministic table.
- **agnes is Chat-Completions-only.** The judge and every adapter reach agnes over
  `/chat/completions`; agnes does **not** implement the OpenAI Responses API.
- **structured mode is best-effort.** agnes's function-calling / `response_format` support is
  flaky; a provider that ignores the schema field degrades to plain generation, so a blank
  `valid` cell means the JSON object did not parse, not that the adapter is broken.
- **Cold-start method.** Cold-start is measured with an empty-stdin probe that never reaches
  the model, so it is pure process/container + runtime spin-up. Warm p50/p95 are full runs
  including the real round-trip; the overhead column is their difference.
- **Native-only adapters.** An adapter without a `run-docker.sh` (e.g. the aisotropy
  reference adapter) is benchmarked in the native form only; its docker row is marked
  skipped, never faked. A missing or errored adapter is absent from a table, never invented.
- **aisotropy multi-turn.** aisotropy's memory tier re-hydrates per turn by design, so its
  memory-mode token spend is the sum across the persist+recall invocations — a real cost,
  and exactly the architectural trade-off this arena exists to surface.
- **Scoped memory: native vs hand-rolled.** aisotropy's tenant isolation is enforced by
  construction in the core runtime (`context.Context`-only `tenant_id` propagation +
  payload-filtered HNSW scan — a constitutional gate), so it ships no arena isolation
  harness; every other framework has no native multi-tenant primitive and hand-rolls a
  compound scope key, which `test-isolation.sh` exercises. A blank aisotropy row is by
  design, not a gap. Each row is the adapter's OWN deterministic script, never faked.
- **Crash recovery: no native support anywhere.** No framework here has native
  crash-recovery; what resumes does so only by persisting each committed turn to a real
  store before the next, and the in-flight turn is **always** lost — the correct, expected
  outcome. Measured by a real two-process `kill -9` (`test-crash.sh`).
- **Observability is a narrow lens (important).** The arena measured **in-process OTel span
  emission** with an in-memory exporter — one deliberately narrow axis. Each framework also
  ships a **native observability platform** this dimension does not fully capture:
  **LangSmith** (LangChain/LangGraph — arguably the richest here; its SDK now has end-to-end
  native OpenTelemetry emit+ingest, so "no native OTel" is true only for the vanilla
  langgraph/langchain-core packages needing a callback→OTel bridge — see
  langchain.com/blog/end-to-end-opentelemetry-langsmith), **Logfire** (pydantic-ai, via
  InstrumentedModel), **Genkit** built-in tracing, **LlamaIndex** instrumentation dispatcher
  + OpenInference OTel, and the **AI SDK** `@ai-sdk/otel` registration — where enabling the
  telemetry flag ALONE emits **0 spans** until `registerTelemetry`/an OTel SDK is wired
  (a real gotcha). Read the table's two axes together, not the arena span count alone.
- **Reproduce.** `cd arenas/live/runner && go run . -frameworks ai-sdk,aisotropy,eino,genkit-go,langgraph,llamaindex,mastra,pydantic-ai,spring-ai -modes qa,rag,tools,memory,structured,stream,safeguard,memory_cross_session,memory_semantic_recall,memory_consolidation,isolation_forgetful -dimensions memory_scoped,isolation_leak,crash_recovery,observability -bench-iters 5`
  (add `-llm-judge` to also run the secondary, opt-in LLM-judge pass; the primary
  deterministic table runs by default and needs no flag).
