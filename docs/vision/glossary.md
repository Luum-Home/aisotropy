# Glossary

Short definitions of terms that recur throughout the knowledge base.
Each entry links to the document that develops it in depth — this glossary doesn't replace
that reading, it indexes it. Alphabetical order.

## Primitive self-improvement

The mechanism by which a **[primitive](#primitive-tool)** (tool) stops being static: when the
[sleep cycle](#sleep-cycle) detects friction (retries from the
[reflection loop](#reflection-loop--output-repair), or the user correcting the bot), an
optimizer agent rewrites the *description* or adds a counterexample. It mutates only
**metadata** interpreted by the LLM — never executable code. Every mutation is audited via
the OTel attribute `agent.optimization.*`. See
[tiered memory](../architecture/memory-tiers.md#primitive-self-improvement-behavioral-memory)
and [observability](../architecture/observability.md#custom-domain-attributes).

## Bits/token/tenant (`bpt`)

The project's **North Star** metric: how many bits the system needs to predict the next
token of a tenant's corpus, with memory hydrated. If `bpt` goes down over time, the system
"knows the tenant better" — measurably, not just narratively. It's instrumented as an OTel
attribute derived from logprobs already computed. See
[Bet 6](../research/bet-06-bits-per-token-metric.md) and
[compression](compression-thesis.md#north-star-bits-per-token-per-tenant).

## Single contract (the struct)

The central pattern of the [thesis](thesis.md#the-struct-as-the-single-source-of-truth): a single Go
struct governs HTTP validation (Huma), the autogenerated OpenAPI 3.1 schema, and the JSON
Schema enforced on the LLM via structured outputs (Gollem) — all at once. One definition,
three uses — it eliminates the intermediate transformation that in other stacks introduces
desync bugs between "what the LLM can return" and "what the API documents." See also
[Gollem](../components/gollem-orchestrator.md).

## Context leak

The risk that [multi-tenancy](#multi-tenancy) exists to eliminate: that data, tokens, or
results from one `tenant_id`/`user_id` leak into another, typically through shared global
state across concurrent requests. Aisotropy avoids this by propagating identity exclusively
via Go's `context.Context`, never in global variables or singletons. See
[derived operating principles](principles.md#derived-operating-principles) and
[multi-tenancy](../architecture/multi-tenancy.md).

## Engram

The atomic unit of [facts/episodic memory](#tiered-memory-memory-temperature): a
distillate of knowledge (a decision, a hard preference, or a summarized episode), not the
raw conversation. It's only stored if it clears the [surprisal](#surprisal)
filter, and it's retrieved by `Relevance × Importance × Recency` scoring. The name comes
from the Gentleman Programming (MIT) pattern that Aisotropy adopts. See
[tiered memory](../architecture/memory-tiers.md#2-facts--episodic-memory-engram-style).

## KB-over-RAG

Karpathy's principle: for **stable and structured** knowledge, a curated, cross-linked
markdown base that the LLM reads directly ("LLM-wiki") beats embedding-based RAG, which
chunks and loses structure. Aisotropy applies this in the product (stable facts go to
[rqlite](../components/rqlite-facts-memory.md) via FTS5, not Qdrant) and in this very
documentation ([OKF](#okf-open-knowledge-format) format). See
[principles](principles.md#3-curated-knowledge-base--rag-for-stable-knowledge).

## LLM OS

Karpathy's mental model, adopted literally by Aisotropy: the LLM is the **CPU**, the context
window is the **RAM**, and everything else (tools, long-term memory, other processes) is
orchestrated peripherals. Gollem = kernel, Huma = syscall layer, `context.Context` = process
descriptor, tiered memory = RAM→disk→long-term hierarchy. See
[architecture overview](../architecture/overview.md#llm-os) and
[principles](principles.md#1-the-llm-os-model).

## Tiered memory (memory temperature)

The framework's central differentiator: memory is organized by **access temperature**, like
a computer's memory hierarchy, instead of a single database. Full detail in
[tiered memory](../architecture/memory-tiers.md). Its three active layers:

- **Working memory** — the last ~10-15 messages plus the active session's
  [summary buffer](#summary-buffer), in [BadgerDB](../components/badgerdb-working-memory.md), µs, in-process.
- **Facts / episodic memory** — the user's journal of [engrams](#engram) (tasks, rules,
  preferences), in [rqlite](../components/rqlite-facts-memory.md) via FTS5, ms.
- **Semantic memory** — embeddings of the tenant's massive/unstructured knowledge, in
  [Qdrant](../components/qdrant-semantic-memory.md), filtered by tenant/user during the HNSW scan.

On top of this sits the [sleep cycle](#sleep-cycle)'s offline batch consolidation.

## Multi-tenancy

**Absolute** isolation between tenants/users: Go's `context.Context` carries `tenant_id` and
`user_id` from Huma down to every memory query, with no global state or singletons in
between. It eliminates [context leak](#context-leak) by construction, not
by convention. See [multi-tenancy](../architecture/multi-tenancy.md) and
[principles](principles.md#derived-operating-principles).

## OKF (Open Knowledge Format)

A Google Cloud specification (v0.1) that formalizes the [LLM-wiki](#kb-over-rag) pattern: a
bundle of markdown with YAML frontmatter, an `index.md` per level, and relative
cross-references that form a knowledge graph — no proprietary SDKs or runtimes. This very
knowledge base is an OKF bundle; it's deliberate dogfooding of the architecture it
documents. See [principles](principles.md#open-knowledge-format-okf) and the
[root index](../index.md).

## Primitive (tool)

A function/tool the LLM can invoke (`FuncTool[P]` in Gollem). Unlike a static tool, in
Aisotropy its *metadata* (description, few-shots, system prompt) is cloned per `user_id` and
can mutate via [self-improvement](#primitive-self-improvement) — the executable code is never
cloned or changed. See [Gollem](../components/gollem-orchestrator.md) and
[tiered memory](../architecture/memory-tiers.md#primitive-self-improvement-behavioral-memory).

## Rate-distortion

Shannon's framework formalizing context assembly: given a fixed token budget (the *rate*),
choose the memory subset that **minimizes distortion** of response quality. It replaces the
"reranking + top-k" heuristic with a measurable, optimal policy. See
[Bet 3](../research/bet-03-rate-distortion-context.md) and
[the compression thesis](compression-thesis.md#the-four-names-for-the-same-operation).

## Reflection loop / output repair

Gollem's self-repair loop: if the LLM returns output that doesn't validate against the
[single contract](#single-contract-the-struct), Gollem re-invokes the model attaching the
exact typing error, up to a bounded maximum of `N` retries — never infinite. Functionally
equivalent to Pydantic AI, native to Go. See [Gollem](../components/gollem-orchestrator.md)
and [thesis](thesis.md#the-struct-as-the-single-source-of-truth).

## Sleep Cycle

Cold memory consolidation: while hot, the system only reads memory and logs raw events to
the [Transactional Outbox](#transactional-outbox); while cold (nighttime/idle), workers spin
up **DataFusion** (Rust) to deduplicate, reconcile contradictions, clean up noise, and detect
friction patterns that trigger [primitive self-improvement](#primitive-self-improvement). See
[tiered memory](../architecture/memory-tiers.md#4-batch-consolidation--the-sleep-cycle) and
[the sleep cycle in DataFusion](../components/datafusion-sleep-cycle.md).

## Sovereignty

The stance that Aisotropy runs 100% on your own hardware, with a 100% permissive
(MIT/BSD/Apache-2.0/ISC) stack, zero copyleft (no BSL or commercial licenses), in-process
wherever latency matters, with megabyte-sized native binaries. Your own data and
infrastructure, auditable end to end — no dependency on a
cloud or proprietary SDK. See [thesis](thesis.md#sovereignty) and
[stack overview](../architecture/overview.md).

## Summary Buffer

A working memory optimization: when the active conversation exceeds N messages, an
asynchronous goroutine condenses the oldest ones into a "session state" paragraph and purges
them from the active buffer. It keeps the context window Gollem sees from growing
indefinitely — a direct application of *context engineering*. See
[tiered memory](../architecture/memory-tiers.md#1-working-memory-short-term) and
[BadgerDB](../components/badgerdb-working-memory.md).

## Surprisal

An information-theoretic measure (`−log₂ P(x)`) of how "surprised" a model is by a given
data point, given the user's already-known profile. A single criterion that replaces
"dedup / noise cleanup / importance scoring" as three separate heuristics: if an
[engram](#engram) candidate has low surprisal (the model already predicted it), it's
redundant and isn't stored. See [Bet 1](../research/bet-01-surprisal-gated-memory.md) and
[the compression thesis](compression-thesis.md#the-four-names-for-the-same-operation).

## Transactional Outbox

A pattern (Saga / Transactional Outbox) implemented in BadgerDB: the chat message and a
pending consolidation event (`outbox:pending:*`) are written in the **same local ACID
transaction** — either both are committed, or neither is. It guarantees *at-least-once* and
idempotent delivery to the cold tiers (rqlite/Qdrant) that the
[sleep cycle](#sleep-cycle) consolidates afterward, without the user waiting
for that sync. See [consistency](../architecture/consistency.md) and
[BadgerDB](../components/badgerdb-working-memory.md).
