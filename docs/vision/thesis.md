# Thesis

## The problem

Building an *enterprise* AI chat/agent — not a demo — demands a set of properties that a
naive "just call the LLM" wrapper never delivers. Four of them shaped this project:

1. **Token cost/efficiency.** You should know exactly what string went to the API. Hidden
   templates, un-reranked RAG, and invisible reasoning loops turn a single question into
   thousands of unaccounted tokens. Aisotropy builds the payload explicitly so every token
   is visible.
2. **Governance and hallucination mitigation.** Prompt engineering alone isn't enough: you
   want input/output guardrails and a structured self-repair loop that fails *closed*.
3. **Standard observability.** Traces per token/cost/tenant following OTel Semantic
   Conventions for LLMs — and, upstream of observability, a *pre-spend* quota gate that can
   reject or degrade before the tokens are spent.
4. **Multi-tenancy with real isolation.** Every byte, token, and millisecond attributable
   to a `tenant_id`/`user_id`, with no context leaks between concurrent requests.

> **A correction to the original framing (2026-07-14).** The first draft of this thesis
> presented all four as sins that "magic frameworks (LangChain and family)" uniquely
> *sabotage*. That was a strawman, and the founding doc should say so plainly. Properties
> 1–3 are table-stakes that a good runtime *needs* — and that several modern competitors
> now provide (see [How this actually compares](#how-this-actually-compares-2026-07-14)
> below). Aisotropy does 1–3 well; it does not do them *alone*. The property that remains a
> genuine differentiator is **#4**, and even that needs stating with care rather than
> bravado. The rest of this document keeps the vision but retires the overclaims.

## The stance: zero magic

The declared enemy is **"magic code"**: automated, opaque, costly design decisions that a
framework makes for you. Aisotropy inverts the relationship: **you build the payload, you
see every token.** The framework is a *clean bridge* between your code and the LLM, not an
abstraction that gets in the way.

The technical consequence is that **granular control is native, not a feature**: it's
solved with traditional software patterns (middleware + Go's `context.Context`) instead of
AI libraries. This is a real posture — but it is a posture about *how* control is expressed,
not a claim that others cannot express control at all.

## The struct as the single source of truth

The piece that ties everything together, and the one that has held up best under scrutiny.
A single Go struct — via [Huma](../components/huma-api.md) at the HTTP edge and
[Gollem](../components/gollem-orchestrator.md) for the LLM — governs **three things at
once**:

- the **validation** of the HTTP input,
- the autogenerated **OpenAPI 3.1 schema** (living doc),
- the **JSON Schema** enforced on the LLM via structured outputs.

If the LLM breaks the contract, Gollem's *reflection loop* re-requests with the exact typing
error, before the client sees anything — and, on the non-streaming `chat` route, fails
*closed* on retry exhaustion rather than falling back to unstructured text. It's the Go
equivalent of `FastAPI + Pydantic AI`.

Honest note on that analogy: **Pydantic AI already ships this same fail-closed loop**
(`raise ModelRetry` feeds the validation error back to the model and raises
`UnexpectedModelBehavior` when retries run out). So the reflection loop is a property
aisotropy *shares* with its own stated model, and holds *versus* runtimes that lack it
(LangChain.js's `createAgent` throws a parse error immediately with no re-feed; Mastra's
`errorStrategy` offers throw/warn/fallback but no self-repair). It is a strength, not a
unique invention.

## Cost control before observability

Aisotropy meters cost per token/cost/tenant, but the sharper edge is *where* the check
sits: a **pre-spend quota gate** (token-bucket in BadgerDB) that rejects with 429 or
degrades to a cheaper model **before** the LLM call is made, per tenant, by construction of
the request lifecycle. That is different from *seeing* cost after the fact — which
LangSmith does well (automatic cost computation) but
as observation only, not a gate, and not per-tenant natively (tenant attribution is DIY
metadata). Pydantic AI's `UsageLimits.check_before_request()` is a genuine pre-spend check,
but scoped per-run, not per-tenant. The aisotropy edge is the **per-tenant pre-spend
gate**, not the dashboard.

## Tiered memory

The real product differentiator isn't the LLM: it's how the system remembers, and how that
memory stays isolated per tenant. Memory is divided by **"temperature" and access cycle**,
like a computer's memory hierarchy. See [tiered memory](../architecture/memory-tiers.md).
This connects directly to Karpathy's **"LLM OS"** model ([principles](principles.md)).

## The surviving differentiator: isolation enforced per storage operation

If token efficiency, fail-closed structured output, and cost observability are table-stakes
that competitors now match, **multi-tenant isolation enforced at the storage layer** is the
property where aisotropy is genuinely distinct — stated precisely, and only as far as an
audit of its own code supports.

What the code actually enforces, verified this run against the source (not against other
docs):

- **Working memory (BadgerDB).** Every read and write is confined to a validated key prefix
  `tenant:{t}:user:{u}:session:{s}`; reserved separator characters (`:`, NUL, newline) are
  rejected in every identity component before a key is built, closing the prefix-forgery
  vector. The `WorkingMemory` API exposes **no method that iterates across prefixes**.
- **Facts memory (SQLite / rqlite + FTS5).** Every scoped read/write carries the SQL
  predicate `tenant_id = ? AND user_id = ?`, byte-identical across the embedded SQLite and
  networked rqlite backends; `Save` rejects a scope mismatch outright.
- **Semantic memory (Qdrant / in-process cosine).** The Qdrant filter is a `Must` condition
  on keyword-indexed `tenant_id` and `user_id` evaluated **during the HNSW traversal** — a
  single-pass in-scan filter, verified in code to be **not** a post-filter. The in-process
  cosine fallback applies the `(tenant, user)` equality check inside the scan loop *before*
  computing similarity, so another tenant's vectors are never scored.
- **Scope as a value-object.** `facts.Scope`, `semantic.Scope`, and `tenancy.Scope` have
  unexported fields; a bare `Scope{}` literal does not compile outside its package, and all
  constructors route through one shared identity validator.

So the safe, precise phrasing is: **isolation is enforced per storage operation —
key-prefix, SQL `WHERE`, and in-scan Qdrant `Must`-filter — such that no request-path code
can issue an unscoped read.**

**Two disclosures, because the founding doc should not hide them:**

1. **One reviewed cross-tenant read exists.** `facts.ExportAll` runs an *unscoped* SELECT
   with no tenant/user predicate. It is not a leak: it lives off the request path, is
   consumed only by the offline sleep-cycle consolidator, and that consolidator
   re-partitions every row back into its own `(tenant, user)` scope before any write-back.
   But it exists on the store interface, so "there is literally no unscoped read path
   anywhere" would be false — there is exactly one, deliberate and confined to the offline
   consolidator. (A separate telemetry store also has operator-aggregate reads that are not
   tenant-scoped; those are an ops view, not the tenant chat path.)
2. **"By construction" describes the storage scoping, not an authenticated identity.** See
   the next section — this is the single most important caveat in this document.

## The authentication gap (be honest about it)

`tenant_id` and `user_id` are **trusted, validated path params — not authenticated
principals.** They arrive as Huma path params constrained to `^[a-zA-Z0-9_-]{1,64}$`,
re-validated for reserved characters, and then propagated. But **no authentication is wired
into the current binary**: the only HTTP middleware is chi's `RequestID` + `Recoverer`.
There is no JWT/Bearer/security-scheme middleware anywhere in the request path today; the
handler code documents JWT auth explicitly as a future "walking-skeleton stand-in."

The consequence, stated plainly: the storage tiers correctly and unbypassably isolate
*whatever* `(tenant_id, user_id)` they are handed — but the current binary trusts the caller
to assert its own tenant and user in the URL. Any client can call
`/v1/tenant/{any}/user/{any}/chat` today. **Binding `tenant_id` to an authenticated
principal is the deploying operator's responsibility** (a JWT/auth middleware in front of
these handlers). "By construction" is a claim about the internal storage scoping being
unbypassable, **not** a claim of an authenticated identity chain — that part is not yet
implemented. See [multi-tenancy](../architecture/multi-tenancy.md) and
[runtime as built](../architecture/runtime-as-built.md).

## How this actually compares (2026-07-14)

A dated reckoning against verified competitive research, so this thesis can be trusted
rather than admired.

| Property | Original claim | Honest verdict |
|---|---|---|
| **Token efficiency** | Frameworks *sabotage* it | Strawman as a blanket accusation — modern frameworks have context trimming/summarization. Aisotropy is explicit about the payload; that's a good property, not a unique sin of others. |
| **Fail-closed structured output** | A differentiator | **Collapsed.** A cross-stack survey (~30 frameworks) shows fail-closed self-repair is common: Pydantic AI, **LangChain-Python** (`OutputFixingParser`), Spring AI 2.0, and CrewAI all have it. aisotropy's only residual nuance is that its loop is *default/runtime-wired* rather than an opt-in wrapper. A table row, not a moat. |
| **Cost observability** | A differentiator | LangSmith computes cost automatically. Aisotropy's real edge is the *pre-spend, per-tenant quota gate*, not the ability to *see* cost — but this is a still-unproven-competitively claim, treated as supporting, not co-equal. |
| **Multi-tenant isolation** | "Real isolation" | **The one surviving differentiator.** Across ~30 frameworks in every major stack, aisotropy is the *only* self-hostable, permissive-OSS runtime that isolates by construction — "strongest / most uniform," not "the only one *in kind*." |

On multi-tenancy specifically, the closest structural competitor is **Google's Agent
Development Kit**. `adk-python` bakes `user_id` into the storage key (nested
`app_name → user_id → session_id` in memory; a composite primary key in the database
backend) — genuinely close in kind. But it is **not** isolation *by construction*:
`google/adk-python#1641` was a real cross-user event disclosure (through v1.4.2) caused by
an events sub-query that *omitted* the `user_id` filter — proving that ADK's isolation is
query-layer filter **discipline** a maintainer can forget. Aisotropy's construction — a
value-object scope threaded into a key prefix / SQL `WHERE` / in-scan Qdrant filter, with no
unscoped request-path read — makes that specific failure class *unrepresentable* on the
tenant path.

So the precise, defensible claims are:

- Aisotropy is **not** "categorically the only runtime with structural isolation" —
  `adk-python` is close in kind (it bakes `user_id` into the storage key).
- Aisotropy **is** uniquely alone across a cross-stack survey of ~30 frameworks (Python,
  TypeScript, Java, .NET, Go, Rust, hosted) as the *only* one that isolates by construction in
  **self-hostable, permissively-licensed OSS**. Every other self-hostable OSS framework either
  has no tenant construct at all (LangChain core, Vercel AI SDK, AutoGen/AG2, Rig, langchaingo,
  Eino, DSPy) or isolates only by developer-passed convention (LlamaIndex, Haystack, CrewAI,
  Mastra, Spring AI, LangChain4j, Semantic Kernel, LangGraph Store, Letta OSS) — where a wrong
  or omitted key silently cross-reads. The *only* by-construction isolation found anywhere else
  is **Google Vertex Memory Bank**, and that lives inside a proprietary GCP service you rent,
  not code you self-host. See the [full matrix](../research/competitive-landscape.md#cross-stack-survey--the-full-isolation-matrix-2026-07-14).
- The moat is **time-boxed** and **bounded**: Google maintains `adk-go` and could port its
  keyed backends; and this survey covered *frameworks/runtimes*, not self-hostable multi-tenant
  *platforms* (Dify, Flowise, Langflow, Cloudflare Agents), whose isolation mechanism is not yet
  verified. The differentiator is real *today*, in a precise lane, and worth defending — not
  eternal, and not yet exhaustive of every self-hostable multi-tenant tool.

And the same caveat as above, because it bounds every claim here: "by construction" means
**unbypassable internal storage scoping**, not authenticated-principal binding. Aisotropy
trusts a validated path param the same way ADK trusts a caller-supplied `user_id`; the
difference is that aisotropy's *storage layer* cannot be made to leak across whatever
identities it is handed, whereas ADK's leak came from a forgettable per-query filter.

## Sovereignty

**100% MIT/Apache-2.0** stack — zero BSL or commercial licenses. Everything runs on your
own hardware, in-process where possible, with megabyte-sized native binaries (not gigabytes
of JVM). Your data, your infrastructure, auditable end to end. See the
[stack overview](../architecture/overview.md).

Being **Go-native and permissively licensed is table-stakes**, not a headline: Eino,
`adk-go`, `langchaingo`, and Genkit share that lane. What sovereignty buys here is the
*combination* — a single self-hostable binary, permissive licensing, in-process memory
tiers, and the storage-layer isolation above — rather than any one of those properties in
isolation.

## What it is and isn't

| Is | Isn't |
|---|---|
| A typed, in-process, per-request agent runtime. | A declarative data pipeline (that would be [Bento](../decisions/index.md), a future radar item). |
| Optimized for interactive chat (SSE, minimal TTFT, ctx cancellation). | Optimized for massive batch ingestion (for that, async workers / DataFusion). |
| Adaptive per-user memory with self-improving primitives. | Per-user executable code cloning (only *metadata* is cloned: prompts, descriptions, few-shots). |
| Isolated per storage operation, with a per-tenant pre-spend cost gate. | Authenticated by construction — auth middleware binding `tenant_id` to a principal is the operator's job (not yet in the binary). |
| Purely sovereign and open source. | Dependent on a cloud or proprietary SDK. |
