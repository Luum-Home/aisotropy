# Go supply-chain maintenance, 2026-10-16

The root scan reproduced the reported reachable vulnerabilities with Go 1.26.6.
The full diagnostic and its original exit code are preserved in
[evidence/go-vulns-2026-10-16](evidence/go-vulns-2026-10-16/).

## Reproduce the original finding

Run from the repository root on macOS/zsh, with Go 1.26.6 already installed,
against the original revision's manifests (`8c62216`):

```sh
GOENV_VERSION=1.26.6 GOTOOLCHAIN=local go mod download
GOENV_VERSION=1.26.6 GOTOOLCHAIN=local GOMAXPROCS=2 GOFLAGS="${GOFLAGS:+$GOFLAGS }-trimpath -p=2" scripts/with-heavy-lane.sh govulncheck ./...
```

The download exited 0. The scan exited 3 and reported 12 reachable
vulnerabilities. See `download.exit` and `govulncheck-before.exit`, with the
corresponding `.log` files. This was a diagnostic before the dependency fixes.

## Dependency and compiler changes

The root and nested modules that already required x/net or gRPC were updated
with `go get golang.org/x/net@v0.60.0 google.golang.org/grpc@v1.83.1` followed by
`go mod tidy`. The exact module list, commands, and exits are in
`module-updates.json`; output is in `root-get.log` and `module-updates.log`.
The same fix covers the streaming and footprint benchmark modules.

The selected x/net release requires `go 1.26.0`, x/sys v0.48.0 and
x/text v0.42.0. The x/text release requires x/tools v0.49.0,
x/mod v0.41.0 and x/sync v0.23.0. gRPC v1.83.1 also raises older adapters'
OpenTelemetry requirements to v1.44.0 and their genproto/rpc minimum.
These are module-graph constraints of the security fixes. The remaining
application dependencies retain their versions.

Reproduce the relevant minimum-version edges with:

```sh
go mod graph | rg '^(golang.org/x/(net@v0.60.0|text@v0.42.0|tools@v0.49.0)|google.golang.org/grpc@v1.83.1) '
go mod why -m golang.org/x/net google.golang.org/grpc golang.org/x/tools
```

The captured output is in `versions-and-constraints.log`. The new language floor
is 1.26.0 where x/net requires it. Existing higher language floors are retained.

The root `.go-version` and the existing Eino `.go-version` now select the
already installed Go 1.26.9. Eino's old pin requested an uninstalled 1.26.4.
All nested Go modules also declare `toolchain go1.26.9`; `toolchain-pins.json`
is the explicit module list. This includes modules without the two libraries,
so their builds also use the patched standard library.

On this host, goenv 3.2.1 discovers a nested module's go.mod before the parent's
`.go-version`. A nested module without a toolchain directive selected the
uninstalled language-floor version and fell back to installed Go 1.26.3.
The installed goenv README documents go.mod toolchain support. Adding
`toolchain go1.26.9` made the same directory select the installed compiler.
The before/after directory-by-directory `GOTOOLCHAIN=local go version` output
is in `versions-and-constraints.log`. No Go installation or global environment
configuration was changed.

## Validation

`validation.json` records the exact command, exit code and output filename for
each build, vet, test and supply-chain run. Commands run sequentially under
`scripts/with-heavy-lane.sh`, with `GOMAXPROCS=2` and `-p=2`. The resource guard
is retained, including its degraded-mode decision in each log.

The initial root test attempt added `-trimpath` to share the build cache across
worktrees. It failed in `bench/answer-quality` and the scopecheck command tests:
`runtime.Caller` produced module paths for fixture/repository lookup. The repository source and tests were left unchanged.
The required ordinary test run and the pre-push hook use the original GOFLAGS
plus `-p=2`, without adding `-trimpath`. Builds, vet and the supply-chain scan
retain `-trimpath`. This is the per-command exception for runtime.Caller fixture
lookups described in the worktree cache guidance.

Absolute worktree prefixes in test diagnostics are normalized to `$REPO_ROOT`
in the published evidence logs. Exit codes and diagnostic messages are retained.

The required root build, vet, ordinary test, standalone govulncheck and full
supply-chain script all exited 0. The scan reported no reachable vulnerabilities;
it still reports one imported-package vulnerability whose vulnerable symbols are
not called. The supply-chain script built/vetted the examples, built all
arenas/bench modules, and passed its root license audit. Eino compiled with
Go 1.26.9; the earlier genkit-go/aisotropy build failures did not recur in this
stable worktree. No cache-missing finding appeared in the final audit.
