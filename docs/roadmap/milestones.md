# Milestones — breakdown by phase

Each phase is a **demonstrable** increment of the [walking skeleton](index.md), not an isolated
module. The rule: a phase is *done* when its criterion can be **verified with a command** (build,
test, curl, benchmark) — never "by vibes" (per the [observability](../architecture/observability.md)
discipline and the [OKRs](okrs.md)). Each phase leaves the system **running**, just more capable.

> **Global status (2026-07-14):** Phases 0–7 implemented and Phase 8 (public adoption surface)
> shipped; Phase 9 (composition surface) partially delivered (ADR-0000..0023 accepted). The
> per-phase checkboxes below are the intended-scope definition; for what is actually **running vs
> dormant vs aspirational** the authoritative node is the
> [reality ledger](../architecture/reality-ledger.md). Phases are numbered the same as in the
> [roadmap index](index.md).

## Phase 0 — Contracts
**Objective:** prove that a Go struct governs HTTP + OpenAPI with no magic.
**Built:** Go module; [Huma](../components/huma-api.md) over chi; typed `ChatRequest`/`ChatResponse`;
`POST /v1/tenant/{tenant_id}/chat` endpoint (stub response); autogenerated `/openapi.json`; healthcheck.
**Definition of done:**
- [ ] `go build ./...` exits 0.
- [ ] The server boots; `curl /openapi.json` returns valid OpenAPI 3.1 derived from the struct.
- [ ] Invalid input (violates the struct) → structured 422, without touching the handler.
- [ ] The path's `tenant_id` reaches the `ctx` (a trace log shows it).

**Touches:** Huma. **Doesn't need:** LLM, API keys, DBs.

## Phase 1 — Walking skeleton
**Objective:** the thinnest working end-to-end flow, with real TTFT.
**Built:** [Gollem](../components/gollem-orchestrator.md) integration; an LLM call with
structured output against the Phase 0 struct; **SSE** streaming; `ctx` cancellation.
**Definition of done:**
- [ ] A message travels Huma → Gollem → LLM → SSE and the client sees tokens streaming (measurable TTFT).
- [ ] Reflection loop demonstrated: given an injected invalid JSON, it re-requests and corrects within ≤ N retries.
- [ ] Closing the request cancels the `ctx` → the LLM call is cut off (verified by token logs).
- [ ] One [OTel](../architecture/observability.md) Span per interaction with `gen_ai.usage.*`.

**Touches:** Huma, Gollem, observability. **Needs:** an LLM provider's credentials.
**Covers:** [OKR O1](okrs.md#o1--the-single-contract-works-phase-0-1).

## Phase 2 — Working memory
**Objective:** the context window never grows unbounded.
**Built:** in-process [BadgerDB](../components/badgerdb-working-memory.md); `tenant:user:session` buffer;
async Summary Buffer past N messages.
**Definition of done:**
- [ ] Session read/write in BadgerDB < 1 ms (benchmark).
- [ ] Summary buffer reduces input tokens ≥ 50% over a long session.
- [ ] A 30-turn conversation maintains coherence with bounded context.

**Touches:** BadgerDB. **Covers:** [OKR O2](okrs.md#o2--working-memory-compresses-without-losing-coherence-phase-2). **Enables:** [Bet 6](../research/bet-06-bits-per-token-metric.md) (measuring bits/token with and without memory).

## Phase 3 — Facts memory
**Objective:** the system remembers across sessions (Engram pattern).
**Built:** [rqlite](../components/rqlite-facts-memory.md) + FTS5; async fact extraction when the
session closes; `Relevance × Importance × Recency` scoring; supersede.
**Definition of done:**
- [x] Async fact extraction writes to the facts store (via the Outbox worker; SQLite default, rqlite backend behind `RQLITE_URL`).
- [x] FTS5 retrieves the top 3-4 engrams by score (Relevance × Importance × Recency).
- [x] Supersede test: a new fact archives/degrades the old one.

**Touches:** rqlite ([ADR-0004](../decisions/0004-facts-memory-rqlite-vs-litefs.md)).
**Covers:** [OKR O3](okrs.md#o3--the-system-remembers-across-sessions-phase-3).
**Enables:** [Bet 1](../research/bet-01-surprisal-gated-memory.md) (surprisal gate over these facts).

---

## Phase 4 — Semantic memory
**Objective:** RAG isolated per tenant, zero leakage.
**Built:** [Qdrant](../components/qdrant-semantic-memory.md) with payload filtering in HNSW;
local reranker ([ADR-0006](../decisions/0006-reranker-cohere-vs-bge-local.md), BGE-v2-m3); UUID v5 idempotency.
**Definition of done:**
- [x] Isolation test: tenant A never sees tenant B's vectors.
- [x] Reranking trims injected context to ≤ 4 fragments while maintaining relevance.
- [x] Reprocessing the same message doesn't duplicate vectors (deterministic UUID v5).

**Touches:** Qdrant, reranker. **Covers:** [OKR O4](okrs.md#o4--rag-isolated-per-tenant-phase-4).

---

## Phase 5 — Consistency
**Objective:** if a node goes down mid-way, memory converges instead of corrupting.
**Built:** [Transactional Outbox](../architecture/consistency.md) in BadgerDB; async workers with
exponential backoff; cold-boot reconciliation.
**Definition of done:**
- [x] Outbox: message + event in the same local ACID transaction in BadgerDB (`AppendWithOutbox`).
- [x] Crash test: close/reopen of the file-backed store keeps pending events; at-least-once retry on a failing sink loses nothing (a literal `kill -9` chaos test is future work).
- [x] Cold boot drains orphaned `outbox:pending:*` entries on startup (`RecoverOutbox`).

**Touches:** BadgerDB, rqlite, Qdrant, consistency. **Covers:** [OKR O5](okrs.md#o5--consistency-under-failure-phase-5).

## Phase 6 — Sleep cycle
**Objective:** the agent is smarter the next day, without touching the core.
**Built:** Rust worker with [DataFusion](../components/datafusion-sleep-cycle.md)
([ADR-0005](../decisions/0005-datafusion-go-rust-boundary.md), batch subprocess); dedup, contradictions,
noise cleanup; primitive self-improvement.
**Definition of done:**
- [x] DataFusion runs in the sleep cycle (Rust subprocess, ADR-0005), produces dedup + cleanup, and the dropped rows are deleted from the live store.
- [x] Friction detection triggers a rewrite of a primitive per `user_id` (the per-user store is `internal/primitives`; a failing agent tool records friction and `primitives.Consolidate` rewrites over-threshold primitives on the sleep-cycle interval — wired in `aisotropy/app.go`). *(Status updated 2026-07-14.)*
- [x] An `agent.optimization.*` OTel event per mutation (auditable).

**Touches:** DataFusion, rqlite, Qdrant. **Covers:** [OKR O6](okrs.md#o6--offline-self-improvement-phase-6).
**Enables:** [Bet 1](../research/bet-01-surprisal-gated-memory.md), [Bet 2](../research/bet-02-working-memory-codec.md) (run in this worker).

## Phase 7 — Granular control (enterprise-ready)
**Objective:** security × cost × behavior, ready for multi-tenant enterprise.
**Built:** full [granular control](../architecture/granular-control.md) — rate limiting + circuit
breaker, scope-based tools, dynamic prompt; physical multi-tenancy ([ADR-0007](../decisions/0007-multitenancy-fisico-db-unica-vs-por-tenant.md), hybrid/tiered).
**Definition of done:**
- [x] Per-tenant rate limiting with a clean 429 (token bucket in BadgerDB, checked before the LLM call; concurrency-tested). Model degradation at 95% quota is delivered (opt-in via `AISOTROPY_CHEAP_MODEL`; `llm.DegradeAt` at `DefaultDegradeThreshold = 0.95`, wired on the streaming path).
- [x] Tools injected according to scopes: without permission → the primitive doesn't exist for the LLM (`internal/tools`).
- [x] Circuit breaker on the LLM client (opens on repeated provider failures; half-open recovery).
- [~] Cost per token per tenant via OTel Span (`gen_ai.usage.*` captured; a dashboard is not built).
- [x] Distroless binary < 50 MB, startup < 1 s, idle RAM < 50 MB (everything except Qdrant). *(Measured 2026-07-09, re-measured 2026-07-14: 32.87 MiB image, ~85 ms startup, ~30.3 MB idle RAM — all PASS; see [distroless](../deployment/distroless.md).)*

**Touches:** everything. **Covers:** [OKR O7](okrs.md#o7--ready-for-enterprise-phase-7).

## Phase 8 — Adoption surface (public API and SDK)
**Objective:** let a third party build *their* bot on top of Aisotropy **without forking** — close
the gap between "functional runtime" and "adoptable framework" (see
[what Aisotropy is](../architecture/what-aisotropy-is.md)).
**Context:** Phases 0–7 make Aisotropy a working multi-tenant agent *runtime*, but its only
extension surface today is **wiring-level**: tools, the `ToolExecutor`, and per-`product_id`
personas are hand-wired in [`cmd/aisotropyd/main.go`](../../cmd/aisotropyd/main.go), and the
reusable packages live under `internal/` (not importable by another module). The demo tools
(`search_docs`, `read_financials`, `write_tasks`) + `echoExecutor` are placeholders, not a product.
**Built (proposed):** a stable public extension surface — either promote the extension packages out
of `internal/` (or expose a versioned façade module), plus a way to register tools / executors /
personas **declaratively** (config or a builder) instead of editing `main.go`; a documented
"add a tool" / "define an agent" path; a worked example consumer bot built *against the public
surface only*.
**Definition of done:**
- [ ] A consumer can register a tool + real `ToolExecutor` and a per-product persona without editing `cmd/aisotropyd/main.go`.
- [ ] The extension packages a consumer needs are reachable from another Go module (out of `internal/`, or via a published façade) with a stated backwards-compatibility contract.
- [ ] An example bot lives in the repo, built only against the public surface, and its build/test is green in CI.
- [ ] `docs/` has a "build your own agent on Aisotropy" guide that does not reference internal wiring.

**Touches:** `cmd/aisotropyd`, `internal/tools`, `internal/agentloop`, `internal/api`, packaging.
**Depends on:** Phase 7 (the runtime it exposes). **Note:** this is an *adoption* phase, not a new
runtime capability — it changes who can build on Aisotropy, not what Aisotropy can do.

## Phase 9 — Composition surface (dual A + B)
**Objective:** make Aisotropy **both** a hostable multi-tenant runtime (A) **and** a composable
agent framework (B) — arbitrary tool topologies, graphs/workflows, multi-agent teams, and
embeddable single-tenant bots — **without regressing tenant isolation** (see
[ADR-0016](../decisions/0016-dual-surface-sealed-runtime-composition-sdk.md)).
**Context:** Phase 8 gave a narrow L1 façade (register a tool + executor + persona). ADR-0013
rejected promoting `internal/` because it would leak `Scope`/`ExportAll`. ADR-0016 reframes that
single rejection into two axes — a **sealed kernel** (never public) and a **composition surface**
(safely public) — held together by one invariant: *a composed node receives an already-scoped
`ctx` and never constructs a `Scope`*. The orchestration engine is already vendored
(`external/gollem/ext/{graph,orchestrator,team,mcp}`); this phase **exposes it under scoping**, it
does not build one.
**Built (sequenced by leverage, ADR-0016):**
1. ✅ **Typed tool args (delivered)** — `WithTypedTool[T]`: the args struct drives the tool schema +
   **server-side validation** (type + `enum`/`min`/`max`/`required`, via a compiled JSON-Schema
   validator) + a fail-closed reflection loop on *inputs* (completes struct-as-contract). SDD:
   [typed-tool-args](sdd/typed-tool-args.md).
2. ✅ **MCP-backed tools (delivered)** — `WithMCPServer(scope, command, args...)`: a stdio MCP server's
   tools become scope-gated Aisotropy tools carrying the server's schema (validated/reflected like any
   typed tool), dispatched via `ext/mcp`; tool *behavior* in any language while the core stays Go.
   (OpenAPI-generated TS/Python *client* SDKs for polyglot callers remain a follow-up.)
3. ✅ **`docker-compose` reference deployment (delivered)** — `docker-compose.yml` boots aisotropyd
   with rqlite (facts) + Qdrant (semantic) ACTIVE so the tiered-memory moat runs, not the in-process
   fallback; `GET /health` probes become real network readiness checks. Sleep-cycle is an opt-in
   overlay (`docker-compose.sleepcycle.yml` + `deploy/Dockerfile.sleepcycle`, bundles the Rust
   worker). Guide: [docker-compose](../deployment/docker-compose.md).
4. **L2 composition SDK** — graph/workflow/team composition wrapping the Gollem `ext/*`, every node
   run under a runtime-injected scoped ctx; plus embeddable `App.Turn(ctx, req)` +
   `WithDefaultTenant` (single-tenant = N=1, Aisotropy-as-library). Built **after** 2–3 real
   consumers shape it.
5. ✅ **Wiring-only declarative config (delivered)** — `aisotropy.Config` + `LoadConfigFile` /
   `OptionsFromConfig`: a YAML/JSON file wires `addr`, `rate_limit`, `cost_pricing`, literal
   `personas`, and `mcp_servers` into builder options that compose with the Go-only options.
   Behavior (Go executors, LLM client) stays code — anti-magic (ADR-0002). Sample:
   `examples/aisotropy.example.yaml`.
**Definition of done:**
- [ ] A consumer registers a typed tool (`WithTypedTool[T]`) from another module; invalid model args
  are repaired by the reflection loop, never silently coerced (SDD R1–R4).
- [ ] A tool can be backed by an MCP server the consumer wrote in a non-Go language; scope-gate still
  enforced.
- [ ] `docker-compose up` boots the runtime with Qdrant + rqlite + sleep-cycle active (moat runs by
  default), verified by `GET /health` = ok with networked probes.
- [ ] A consumer composes a multi-step graph / multi-agent team against the public L2 surface, and a
  test proves an L2 node cannot obtain a `Scope` (the ADR-0016 invariant is machine-enforced).
- [ ] Aisotropy runs embedded via `App.Turn` in single-tenant mode with no HTTP server.

**Touches:** `aisotropy/` (façade + new L2), `internal/llm` (ToolSpec/ToolCall), `internal/tools`,
`internal/agentloop`, `internal/api`, `external/gollem/ext/*` (wrapped), packaging (compose).
**Depends on:** Phase 8 (L1 façade), ADR-0016. **Note:** unlike Phase 8 (pure adoption), this phase
*adds* a runtime capability — composition — while keeping the kernel sealed.
