# Client SDKs — typed clients from the OpenAPI contract

aisotropyd serves its own contract at **`GET /openapi.json`** (OpenAPI 3.1, generated by Huma from
the Go request/response structs — see [API versioning policy](api-versioning-policy.md) for why the
struct *is* the contract). Any consumer, in any language, generates a typed client from that one
document. This guide shows two reference clients — **TypeScript** and **Python** — plus a single-file
**reference chat UI**, all under [`examples/clients/`](../../examples/clients).

Everything here is a *reference*, not a shipped package: it exists so a third party can see exactly how
to consume the runtime and copy the pattern into their own repo.

## What the contract exposes

The chat surface (there are also `ask`, `agent`, `agui`, `aisdk`, and `knowledge` routes — the same
generation flow covers all of them):

| Route | Method | Request | Response |
|---|---|---|---|
| `/v1/tenant/{tenant_id}/user/{user_id}/chat` | POST | `ChatRequest` (JSON) | `ChatOutputBody` (JSON), `ErrorModel` on error |
| `/v1/tenant/{tenant_id}/user/{user_id}/chat/stream` | POST | `ChatRequest` (JSON) | `text/event-stream` (SSE), `ErrorModel` on error |

- **Identity is in the path.** `tenant_id` and `user_id` are path params — the isolation boundary.
  They are never taken from the body.
- **`ChatRequest` required fields**: `prompt`, `product_id`, `session_id`. Optional: `scopes`
  (gate tool access), `model_preference`, `images`.
- **Auth**: a bearer token (`Authorization: Bearer <jwt>`) is required unless the server runs in
  NoAuth dev mode (`AISOTROPY_ALLOW_NOAUTH=1`). See [services-config](../../.claude/rules/services-config.md).
- **SSE frames**: the stream route emits `event: token|done|error` with a JSON `data:` payload
  (`StreamTokenEvent{text}`, `StreamDoneEvent{tenant_id}`, `StreamErrorEvent{message}`). Per the
  transport bake-off, SSE-over-HTTP is the default streaming wire format; the route returns
  `text/event-stream`.

## Step 0 — get the spec

Boot the keyless stub binary on loopback and save the spec:

```bash
AISOTROPY_ALLOW_NOAUTH=1 AISOTROPY_ADDR=127.0.0.1:8080 go run ./cmd/aisotropyd &
curl -s http://127.0.0.1:8080/openapi.json -o examples/clients/openapi.json
```

A snapshot is already committed at [`examples/clients/openapi.json`](../../examples/clients/openapi.json)
so client generation is reproducible without a running server.

## TypeScript client

Stack (both **MIT**): [`openapi-typescript`](https://github.com/openapi-ts/openapi-typescript) generates
`paths`/`components` *types* from the spec; [`openapi-fetch`](https://github.com/openapi-ts/openapi-typescript/tree/main/packages/openapi-fetch)
is a ~6 kB typed fetch wrapper for the JSON routes. openapi-fetch does **not** consume SSE, so the
streaming transport is a small hand-written `fetch` + `ReadableStream` reader typed against the same
generated `Stream*Event` types.

```bash
cd examples/clients/typescript
npm install
npm run generate      # openapi-typescript ../openapi.json -o ./src/schema.ts
npm run typecheck     # tsc --noEmit  → the CI gate
```

- [`src/schema.ts`](../../examples/clients/typescript/src/schema.ts) — generated (do not edit).
- [`src/client.ts`](../../examples/clients/typescript/src/client.ts) — `chat()` (JSON) and
  `streamChat()` (SSE) typed against the generated schema.
- [`src/example.ts`](../../examples/clients/typescript/src/example.ts) — runnable demo.

```ts
import { chat, streamChat } from "./client.js";
const opts = { baseUrl: "http://127.0.0.1:8080", token: process.env.AISOTROPY_TOKEN };

const out = await chat(opts, "acme", "alice",
  { prompt: "Hi", product_id: "analytics-v1", session_id: "s1" });
console.log(out.reply, out.tenant_id, out.stub);

await streamChat(opts, "acme", "alice",
  { prompt: "Stream a greeting", product_id: "analytics-v1", session_id: "s1" },
  { onToken: (e) => process.stdout.write(e.text),
    onDone:  (e) => console.log("done", e.tenant_id) });
```

Run the demo live: `npx tsx src/example.ts` (with the server up on `AISOTROPY_BASE_URL`).

## Python client

Generator (**MIT**): [`openapi-python-client`](https://github.com/openapi-generators/openapi-python-client)
emits a typed `httpx` + `attrs` client. It generates the JSON-route calls and all request/response
models, but — like most OpenAPI generators — does **not** emit an SSE consumer. The streaming transport
is a small `httpx.stream` reader ([`sse.py`](../../examples/clients/python/sse.py)) that decodes each
frame into the **same generated** `StreamTokenEvent` / `StreamDoneEvent` / `StreamErrorEvent` models.

```bash
cd examples/clients/python
python3 -m venv .venv && . .venv/bin/activate
pip install openapi-python-client==0.29.0
openapi-python-client generate --path ../openapi.json --meta none \
  --output-path ./aisotropy_client --overwrite   # regenerate aisotropy_client/
pip install -r requirements.txt                    # runtime deps only (httpx, attrs)
python example.py                                  # runnable demo
```

- [`aisotropy_client/`](../../examples/clients/python/aisotropy_client) — generated package.
- [`sse.py`](../../examples/clients/python/sse.py) — typed SSE transport.
- [`example.py`](../../examples/clients/python/example.py) — runnable demo (chat + stream).

```python
from aisotropy_client import Client
from aisotropy_client.api.default import chat as chat_api
from aisotropy_client.models.chat_request import ChatRequest
from sse import stream_chat
from aisotropy_client.models.stream_token_event import StreamTokenEvent

client = Client(base_url="http://127.0.0.1:8080")
req = ChatRequest(prompt="Hi", product_id="analytics-v1", session_id="s1")
out = chat_api.sync(tenant_id="acme", user_id="alice", client=client, body=req)
print(out.reply, out.tenant_id, out.stub)

for ev in stream_chat("http://127.0.0.1:8080", "acme", "alice", req):
    if isinstance(ev, StreamTokenEvent):
        print(ev.text, end="")
```

## Reference chat UI

[`examples/clients/chat-ui.html`](../../examples/clients/chat-ui.html) is a single static HTML/JS file
— no framework, no build step. Open it in a browser, set the Base URL / Tenant / User / (optional)
bearer token, and it streams a chat over SSE using the same Fetch + `ReadableStream` transport as the
TS client. The **Stop** button calls `AbortController.abort()`, which cancels the fetch — and the
runtime honors context cancellation, so the upstream LLM call stops too.

> **CORS note.** A browser page served from a different origin than aisotropyd needs the server to send
> CORS headers. For a local demo, serve the file from the same origin (e.g. behind a reverse proxy), or
> point Base URL at a same-origin proxy in front of the runtime.

## Regenerating after a contract change

Because the Go struct is the OpenAPI contract, a struct change is a contract change. To pick it up:

1. Re-fetch `examples/clients/openapi.json` from a running server (Step 0).
2. TS: `npm run generate && npm run typecheck`. Python: re-run `openapi-python-client generate`.
3. A **breaking** change will surface as a type/import error in the regenerated client — that is the
   safety property. See [API versioning policy](api-versioning-policy.md) for how breaks are gated and
   announced.
